# 대고객 서비스 운영 계획

이 문서는 출시 후 고객지원·안전·장애·공식정보 품질을 실제로 운영하기 위한 기준안입니다. 아래 시간은 인력과 운영시간이 확정되기 전의 **권장 목표**이며 고객에게 약속하기 전에 운영주체가 승인해야 합니다.

## 출시 차단 조건

다음 항목 중 하나라도 미완료면 공개 출시를 진행하지 않습니다.

- 운영 법인·담당자·고객지원 이메일·개인정보 보호책임자 미확정
- 이용약관·개인정보 처리방침·커뮤니티 정책 법률 검토 미완료
- 운영 Supabase RLS 통합 테스트와 계정삭제 종단 테스트 미통과
- 신고 큐를 매일 확인할 담당자와 긴급 에스컬레이션 연락망 미지정
- 오류 모니터링, 백업, 복구 절차와 배포 롤백 연습 미완료
- 공식정보 문서의 출처·효력일·최종 검수자·재검토일 미기록

## 문의 상태와 처리 기준안

| 유형 | 최초 확인 목표 | 처리 원칙 |
| --- | --- | --- |
| 신체 위험·범죄·자해 | 앱에서 해결하지 않음 | 관할 긴급기관을 우선 안내하고 내부 안전 담당자에게 즉시 전달 |
| 개인정보 노출·계정 탈취 | 운영시간 4시간 이내 | 노출 콘텐츠 임시 숨김, 계정 세션 확인, 증적 보존과 담당자 에스컬레이션 |
| 혐오·괴롭힘·사기 신고 | 1영업일 이내 | 신고 내용과 반복 위반 이력을 확인하고 정책에 따른 일관된 조치 |
| 공식정보 오류·오래된 출처 | 1영업일 이내 | 해당 답변을 표시 제한하고 원문·효력일·검수 기록을 재확인 |
| 로그인·일정·일반 문의 | 2영업일 이내 | 재현 정보 확인 후 답변, 해결되지 않으면 기술 담당자에게 전달 |

문의 상태는 `접수 → 확인 중 → 답변 완료 → 종료`로 관리합니다. 상태 변경과 운영자 조치는 감사 가능한 기록으로 남깁니다.

## 장애 대응

1. 오류율, 로그인 실패, Edge Function 지연, 신고 적체와 공식정보 무응답률을 모니터링합니다.
2. 고객 영향과 데이터 위험에 따라 심각도를 정하고 담당자와 의사결정자를 호출합니다.
3. 데이터 손상이나 잘못된 공식정보 가능성이 있으면 관련 기능을 우선 중지합니다.
4. 복구 후 영향 범위, 원인, 재발 방지와 고객 공지 필요 여부를 기록합니다.
5. 중대한 장애는 5영업일 안에 내부 회고를 완료합니다.

## 공식정보 품질 운영

- 정부·공공기관 원문만 후보로 등록하고 출처 URL, 발행기관, 문서 유형, 효력일과 확인일을 저장합니다.
- 자동 수집 결과는 답변에 사용하기 전 사람의 승인을 거칩니다.
- 근거가 없거나 충돌하면 답을 생성하지 않고 1345 또는 담당 기관 확인을 안내합니다.
- 오류 신고가 들어온 답변은 원문 재검수 전까지 품질 검토 대상으로 표시합니다.
- 정기 재검토 주기와 긴급 변경 감지 담당자를 문서별로 지정합니다.

## 개인정보와 보안 운영

- 여권번호·외국인등록번호를 가입 필드로 수집하지 않습니다.
- 고객문의와 AI 질문에 고유식별정보가 포함되지 않도록 입력 단계와 서버 로그 단계에서 방어합니다.
- 최소 권한, 키 회전, 퇴사자 권한 회수와 분기별 접근권한 검토를 시행합니다.
- 백업 복구 테스트, 계정삭제 검증과 보유기간 만료 삭제 작업을 정기 실행합니다.

## 출시 후 핵심 지표

- 로그인 성공률과 온보딩 완료율
- 공식정보 답변의 출처 표시율, 근거 없음 비율, 오류 신고율
- 신고·문의 최초 확인시간과 미처리 건수
- 7일·30일 재방문율과 일정 완료율
- 앱 비정상 종료 없는 세션 비율과 주요 화면 오류율

지표 수집 전 분석 동의, 수집 항목, 보유기간과 개인정보 처리방침의 일치 여부를 검토합니다.
